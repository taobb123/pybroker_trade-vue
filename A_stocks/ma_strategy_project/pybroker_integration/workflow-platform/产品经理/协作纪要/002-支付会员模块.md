## A. 产品经理

### 1. 目标

补齐商业化会员闭环的**产品壳**：用户能看清套餐、发起「升级」、查看订单；支付通道本期 mock，不自研支付内核。

### 2. 范围

**做**

| 能力 | 说明 |
|------|------|
| 套餐墙 | Free / Pro / Team 三档对比；权益结构清晰 |
| 当前档位 | 展示用户当前 `plan` |
| 升级动作 | Pro：可 mock 支付成功并升档；Team：展示但不可购（联系客服） |
| 订单列表 | 订单号、时间、金额、套餐、状态 |
| 入口 | 账户菜单「账单/会员」；用户中心可跳转 |

**不做**

- 微信/支付宝/Stripe 真支付
- 发票税务、优惠券中台、自动续费扣款
- 复杂营销长页

### 3. 关键路径

```
已登录
  → 账户菜单「会员 / 账单」或用户中心「账单」
  → 套餐墙（见当前档）
  → 选择 Pro → Mock 支付成功 → plan=pro → 订单多一条 paid
  → 订单页可查
Team → 仅「联系客服」，不改 plan
```

### 4. 硬约束

1. 不自研支付内核；mock 回调即可验收  
2. 套餐页短、克制（工具站气质）  
3. 依赖登录态；未登录引导登录  
4. Free→Pro 可降回 Free（演示用，可选）  
5. 额度数字可用占位文案，结构正确即可  

### 5. 验收标准

- [ ] 有套餐页：三档结构 + 当前档标识  
- [ ] Mock 升级 Pro 后账户菜单/用户中心显示 Pro  
- [ ] 有订单列表（含 mock 成功单）  
- [ ] Team 不可一键购买  
- [ ] 无真实支付 SDK
