## A. 产品经理发言

### 1. 目标

为量化工作流平台补齐可商业化的三块基础设施产品设计，使后续能：

- 识别用户（登录 / 账户）
- 区分权益（Free / Pro / Team）并完成付费
- 看见用量与访问（运营与产品决策）

对象：个人量化研究者 → 后续小团队（Team 预留，本期可不实现协作）。

### 2. 三大模块 · 范围与关键路径

---

#### ① 用户系统

**产品意图**：照搬主流 AI SaaS 账户体验（气质参考 ChatGPT；偏工具时可偏 Cursor 干净度）。不创新资料字段。

**做**

| 能力 | 说明 |
|------|------|
| 登录入口 | 邮箱/手机为主路径意图；第三方（微信/Google/GitHub）可分期 |
| 账户菜单 | 头像、昵称、邮箱 → Settings / Billing / Logout |
| 用户中心页 | 个人资料、安全、通知（可后）、账单入口、会员入口、API Key（适合量化，可后） |
| 资料字段上限 | **仅**：头像、昵称、邮箱、手机号、会员等级、邀请码 |

**不做**

- 性别 / 生日 / 兴趣等资料堆砌
- 自研密码加密、会话内核、OAuth 协议栈（必须接第三方 Auth）
- 本期强制 Workspace / Members（Notion 协作态延后）

**关键路径**

```
未登录访问受保护能力
  → 登录页（邮箱/手机 ± 第三方）
  → 进入工作台
  → 左上角账户菜单 → 用户中心 / 账单 / 退出
```

**体验约束**

- 登录页克制：少字段、少装饰
- 用户中心是「短设置页」，不是社交主页

---

#### ② 支付会员

**产品意图**：照搬 ChatGPT Plus / Cursor Pro 式套餐墙 + 订单列表；支付走官方通道，不自研清算。

**做**

| 能力 | 说明 |
|------|------|
| 套餐展示 | Free / Pro / Team（或 Enterprise 联系客服）三档对比 |
| 权益文案 | 次数、高级策略、云端保存等——**具体额度数字产品可后定，结构先定** |
| 支付方式意图 | 国内：微信 / 支付宝；海外预留 Stripe |
| 订单 | 订单号、支付时间、金额、状态、下载发票（可后） |
| 权限挂钩意图 | 角色：Free / Pro / Team，用于限制运行次数、能力开关 |

**套餐墙信息结构（验收用骨架）**

```
Free  ¥0     · 基础能力 · 每日有限次数
Pro   ¥??    · 更高/无限次数 · 高级策略 · 云端保存
Team/Enterprise · 联系客服或席位制（结构预留）
```

**不做**

- 自研支付网关、分账、发票税务内核
- 复杂促销引擎、优惠券中台（首期可无）
- 把会员页做成营销长页（保持工具站克制）

**关键路径**

```
工作台内点击「会员」或触发权益墙
  → 套餐对比
  → 选择 Pro → 支付（微信/支付宝）
  → 回跳成功 → 会员等级更新 → 订单可查
```

---

#### ③ 流量访问统计

**产品意图**：运营向 Dashboard，信息架构照搬 Cloudflare / Vercel / Supabase 一类控制台；**指标采集不自研分析引擎**。

**做（展示层）**

| 区块 | 内容 |
|------|------|
| KPI 行 | 今日访问、昨日访问、在线人数（或活跃）、工作流运行次数；（可选）平均响应、Token 消耗 |
| 趋势 | 近 30 天访问折线 |
| Top 列表 | Top Workflow / Top Strategy / Top API / Top User（有数据再亮，无则空态） |

**不做**

- 自研埋点仓库、会话回放、复杂归因
- 为「像官网」而堆无业务意义的虚荣指标
- 与量化「运行结果报告」混成同一页职责（统计 ≠ 策略报告）

**关键路径**

```
登录后（建议仅管理员/主人可见，首期可先全员可见占位）
  → 侧栏「总览 / 用量」
  → KPI + 趋势 + Top
```

**产品澄清**：本模块是**平台访问与用量统计**，不是策略回测报告页。

---

### 3. 硬约束（跨三模块）

1. **拼装优先**：Auth / Pay / Analytics 内核外购或托管；本仓库只做壳、对接与权限映射。
2. **字段与页面克制**：用户资料字段上限如上；会员页短、统计页结构化，禁止资料/营销堆砌。
3. **与核心业务解耦**：三模块失败或未接通时，本地开发仍应能跑工作流（dev bypass / mock 用户允许，由工程定）。
4. **忽略扣子**：任何方案不得依赖扣子工作流才能完成这三模块。
5. **技术名词非强制**：计划中的 Clerk / Supabase / Stripe / Umami / Next.js 等仅为参考；工程师自选，但须满足「不自研内核」。

### 4. 优先级（产品拍板）

| 顺序 | 模块 | 理由 |
|------|------|------|
| 1 | 用户系统（登录 + 账户壳 + 资料上限） | 会员与统计都依赖「是谁」 |
| 2 | 支付会员（套餐墙 + 订单壳 + 角色枚举） | 商业闭环；支付通道可先沙箱/占位 |
| 3 | 流量访问统计（KPI + 趋势 + Top 壳） | 可先接 mock / 第三方，后接真数据 |

### 5. 验收标准（本轮对齐后的「产品完成」定义）

**用户系统**

- [ ] 有登录页与账户菜单路径
- [ ] 用户中心仅含允许字段（或对应空态）
- [ ] 无自研 Auth 内核；对接方式可说明

**支付会员**

- [ ] 有 Free/Pro/Team 结构的套餐页
- [ ] 有订单列表骨架
- [ ] 权限角色枚举存在（即使支付仍为 mock）

**流量访问统计**

- [ ] 有独立统计向 Dashboard 区块：KPI + 趋势位 + Top 位
- [ ] 与策略报告页职责分离
- [ ] 采集方案可说明（第三方或暂 mock），非自研分析引擎

## B. AI全栈工程师回应

### 1. 现状

| 项 | 现状 |
|----|------|
| 前端 | Vue 3 + Vite + shadcn-vue 工作台已有 |
| 路由 | Dashboard / Workflows / Runs / Reports —— **无** 登录、账户、会员、订单页 |
| 身份 | 无登录态；运行历史在 `localStorage` |
| 统计 | Dashboard 偏工作流结果预览，**不是**访问分析控制台 |
| 支付 | 无 |

### 2. 选型方向（在约束内自主；可替换等价物）

| 模块 | 倾向方案 | 说明 |
|------|----------|------|
| 用户系统 | 国内优先可后续接微信/手机；工程可先 **JWT/Session + 托管 Auth（如 Supabase Auth）或现有 FastAPI 薄封装** | 禁止自研 OAuth/密码学；首期可用 **Dev Mock User** 打通壳 |
| 支付会员 | 套餐/订单 **先做前端壳 + 角色枚举（Free/Pro/Team）**；通道：**微信/支付宝官方 SDK**（国内），Stripe 预留接口形状 | 首期支付可 mock 成功回调 |
| 流量统计 | 展示用现有 KPI/ECharts；采集：**Umami 或等价** / 或后端聚合运行次数；无第三方时 **mock 序列** | 禁止自研完整分析产品 |

**明确偏差**：不采用计划示例中的 Next.js 重写；三模块做在现有 Vue 壳内。

### 3. 建议信息架构增量

```
侧栏（增量）
  总览        → 升级为「用量/访问」统计向（或拆「工作台」与「用量」）
  工作流      → 保持（核心，本轮少动）
  运行/报告   → 保持
  会员        → 新增套餐页
  ────────
  账户菜单    → 用户中心 / 账单（订单）/ 退出
```

路由草案（工程师可改名，职责不变）：

- `/login`
- `/account`（用户中心）
- `/billing/plans`（套餐）
- `/billing/orders`（订单）
- `/usage` 或强化现有 `/` 为统计向（需与「工作流总览」职责划清）

### 4. 下一刀建议（最小可验收切片）

**只做三模块的「可点击壳 + 角色模型 + mock 数据」，不接真支付/真短信。**

1. 登录页 + 本地/ mock 登录态 + 账户菜单  
2. 用户中心页（字段上限）  
3. 套餐页（三档）+ 订单列表空态/mock  
4. `plan: free|pro|team` 写入客户端或假 session  
5. 统计 Dashboard：KPI + 假趋势 + Top 空态/mock  

真 Auth / 真支付 / 真 Umami → 下一轮协作。

### 5. 请产品确认的开放问题

1. 统计页与当前「总览（工作流结果）」是 **同一路由改职责**，还是 **拆成两个入口**？  
   - 工程师默认：**拆开**——`/` 或「用量」做统计；工作流结果留在工作流/报告。  
2. 首期登录是否允许 **仅邮箱+验证码占位 / 甚至一键 Mock 登录**？  
   - 工程师默认：**允许 Mock 登录**，以便先验收壳。  
3. Team 档是否首期展示但不可买（联系客服）？  
   - 工程师默认：**是**。
