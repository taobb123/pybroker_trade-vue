## A. 产品经理

### 1. 目标

提供**平台访问与用量**向的运营 Dashboard，与策略报告/工作流总览职责分离；采集不自研分析引擎。

### 2. 范围

**做**

| 区块 | 内容 |
|------|------|
| KPI | 今日访问、昨日访问、环比；在线/活跃；工作流运行次数 |
| 趋势 | 近 30 天访问折线 |
| Top | Top Workflow / Top Strategy / Top API / Top User（无数据空态） |

**不做**

- 自研埋点仓库、会话回放、国家/浏览器复杂归因产品
- 与「总览（工作流结果）」混为同一页
- 真 Umami 对接（下期；本期 mock）

### 3. 关键路径

```
侧栏「用量」
  → KPI + 趋势 + Top 列表
  → 可注明数据为 Mock / 部分来自本地运行历史
```

### 4. 硬约束

1. 独立路由，不替换现有「总览」工作流页  
2. 不自研分析引擎  
3. 工具站克制布局（Cloudflare/Vercel 信息结构，非营销页）  

### 5. 验收

- [ ] 独立「用量」入口与页面  
- [ ] KPI + 30 日趋势 + Top 区块齐全  
- [ ] 与 `/` 总览职责分离  
- [ ] 无自研采集后端（mock ± 本地运行次数）
