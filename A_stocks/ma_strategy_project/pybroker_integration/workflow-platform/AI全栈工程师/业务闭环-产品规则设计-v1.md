## 1. 目标闭环

把「能点的壳」连成可验证的商业路径：

```
用户（身份）
  → 套餐 / 支付（权益生效）
  → 配额与权限（运行前校验）
  → 工作流执行（消耗配额）
  → 用量 / 订单（可审计）
```

本期规则服务于 **MVP 收费验证**，不追求复杂计费中台。

---

## 2. 套餐与配额（核心表）

| 档位 | 价格（展示） | 日运行配额 | 高级策略 | 报告导出 | 云端保存 | 备注 |
|------|--------------|------------|----------|----------|----------|------|
| Free | ¥0 | **10** 次/自然日 | ❌ | ❌ | ❌ | 默认证件 |
| Pro | **¥39**/月 | **100** 次/自然日 | ✅ | ✅ | 预留（规则开、实现后置） | 可自助 Mock/真支付升档 |
| Team | 联系客服 | **不限**（`-1`） | ✅ | ✅ | 预留 | **不可自助购买** |

### 计数口径

| 规则 ID | 定义 |
|---------|------|
| `quota.unit` | 一次成功或失败的 **工作流 `run` 调用** 计 1 次（含被中途停止的已发起 run） |
| `quota.window` | **自然日**（本地时区日切 00:00）；跨日清零 |
| `quota.exempt` | 仅浏览步骤列表、打开报告、查看历史 **不计** 配额 |
| `quota.block` | 当日已用 ≥ 日配额时，**禁止新 run**，提示升级 |
| `quota.display` | 工作流页/账户区展示「今日剩余 / 日上限」 |

### 权益开关（能力门控）

| 能力 key | Free | Pro | Team |
|----------|------|-----|------|
| `workflow.basic` | ✅ | ✅ | ✅ |
| `workflow.advanced` | ❌ | ✅ | ✅ |
| `report.export` | ❌ | ✅ | ✅ |
| `workspace.cloud_save` | ❌ | 预留 | 预留 |
| `team.seats` | ❌ | ❌ | 预留 |

> **高级策略**：首期以步骤元数据 `tier: 'advanced' | 'basic'`（或缺省 basic）判定；无标记一律按 basic。

## 3. 会员生命周期

| 事件 | 规则 |
|------|------|
| 注册 / Mock 登录 | `plan=free`，`expire_at=null`，当日配额窗口初始化 |
| 支付成功（Pro） | `plan=pro`；`expire_at=支付成功时刻+30天`；写入订单 `paid`；**立即生效** |
| Pro 到期 | 自动回落 `plan=free`；不追溯已用配额；未用 Pro 配额作废 |
| 降为 Free（自测/客服） | 立即按 Free 门控；不自动退款（MVP） |
| Team 开通 | 仅人工/后台标记；`expire_at` 可空或合同期；禁止套餐墙自助 |

### 订单最小字段（逻辑模型）

```
order_id, user_id, plan, amount_yuan, status, paid_at, channel, period_days
```

状态：`pending | paid | cancelled`（MVP 以 paid 为主）。

## 4. 用户与权限

| 规则 | 内容 |
|------|------|
| 身份 | MVP 继续允许 Mock 登录；真 Auth 不改变本表配额语义 |
| 资料字段 | 仍遵守上限：头像/昵称/邮箱/手机/会员等级/邀请码 |
| 鉴权 | 未登录：**允许**浏览与本地跑（开发友好）；若 `enforceAuthForRun=true`（默认 **false**，收费验证期可改 true）则 run 前必须登录 |
| 角色 | 仅 `plan` 三档；不做细粒度 RBAC（Team 席位后置） |

---

## 5. 用量与统计

| 规则 | 内容 |
|------|------|
| 职责 | `/usage` = 平台访问与用量；`/` = 工作流结果总览；**不合并** |
| 访问量 | 可继续 Mock，直到接入 Umami/后端 |
| 运行次数 | **以真实 run history 为准**（与配额同源事件） |
| Top Workflow | 按 `stepId` 聚合 run 次数 |
| 审计 | 每次 run 应能关联 `user_id`（登录时）与 `plan_snapshot`（发起时档位） |

---

## 6. 支付（规则层，非实现层）

| 规则 | 内容 |
|------|------|
| 成功定义 | 收到可信回调 **或** MVP Mock 确认 → 写订单 + 改 `plan` + 设 `expire_at` |
| 失败 | 不改 `plan`；可留 `pending` 订单（后置） |
| 渠道 | 国内：微信/支付宝；海外：Stripe 预留；**禁止自研清算** |
| 展示 | 套餐文案必须与本文配额数字一致（单一配置源） |

---

## 7. 实现分期（工程师排期建议）

| 切片 | 内容 | 验收 |
|------|------|------|
| **R1** | `businessRules.ts` + UI 展示剩余次数/档位权益与规则表一致 | 文案与数字同源 |
| **R2** | 本地配额计数 + run 前拦截 + 升级引导 | Free 超 10 次无法再跑 |
| **R3** | `expire_at` + 到期回落 Free | 改时钟/改 expire 可测 |
| **R4** | 高级策略门控 | advanced 步骤 Free 不可跑 |
| **R5** | 真支付回调接线 | 回调后 plan/订单与规则一致 |

**当前交付**：规则文档 + 配置源 + 同步纪要（R1 配置已落库；R2 起为实现刀）。

## 8. 请产品经理确认的默认假设

若无异议，视为批准：

1. Free **10**/日、Pro **100**/日、Team 不限  
2. Pro **¥39**/30 天  
3. 配额按 **发起 run** 计，含失败  
4. 未登录仍可跑（`enforceAuthForRun=false`）直至收费验证期再收紧  
5. Team 仅人工开通
